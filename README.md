# OpenTofu / Terraform provider `nitra/hydra`

Manages a **self-hosted [Ory Hydra](https://github.com/ory/hydra)** (built and tested against
`oryd/hydra:v26.2.0`) through its Admin API, on `terraform-plugin-framework` (protocol 6).

| Kind | Name | Purpose |
|---|---|---|
| resource | `hydra_oauth2_client` | OAuth 2.0 clients: every field of Hydra v26.2.0's `OAuth2Client`, all 13 per-client token lifespans, write-only client secret |
| resource | `hydra_trusted_jwt_grant_issuer` | Trust relationships for the RFC 7523 jwt-bearer grant |
| data source | `hydra_trusted_jwt_grant_issuers` | List trusts (e.g. to find IDs for `import`) |

Documentation: [`docs/`](docs/) (generated by `tfplugindocs`), including the guide
[Forgejo Actions -> Hydra via jwt-bearer](docs/guides/forgejo-jwt-bearer.md) with the complete
configuration from [`examples/7n/`](examples/7n/main.tf).

```hcl
terraform {
  required_version = ">= 1.11.0" # write-only arguments
  required_providers {
    hydra = { source = "nitra/hydra", version = "~> 1.0" }
  }
}

provider "hydra" {
  endpoint = "http://hydra-admin.hydra.svc:4445" # or HYDRA_ADMIN_URL
}
```

## Differences from upstream `svrakitin/terraform-provider-hydra`

This repository is a fork of [svrakitin/terraform-provider-hydra](https://github.com/svrakitin/terraform-provider-hydra)
(git history preserved), rewritten from SDKv2 to the Plugin Framework:

* **Plugin Framework only** (no mux), protocol 6, published as `registry.opentofu.org/nitra/hydra`.
* **API client generated from the exact server tag** - `internal/httpclient` is vendored from Hydra
  `v26.2.0` via a `replace` directive instead of the outdated `hydra-client-go/v2 v2.1.1`
  (see [`internal/httpclient/README-VENDOR.md`](internal/httpclient/README-VENDOR.md)).
* **`hydra_jwks` resource and data source removed**: they put private keys into state. Read
  public JWKS with `data "http"`.
* **`hydra_oauth2_client`**
  * `client_id` is required and forces replacement; import ID = `client_id`.
  * All `OAuth2Client` fields of v26.2.0 incl. `skip_consent`, `skip_logout_consent`,
    `access_token_strategy`, and all 13 lifespans (device authorization grant included).
  * The secret is **never stored in state**: `client_secret_wo` (write-only, OpenTofu >= 1.11) +
    `client_secret_wo_version` (bump to push a rotated secret). Creating a client that
    authenticates with a secret (`client_secret_basic` - the default -, `client_secret_post`,
    `client_secret_jwt`) without `client_secret_wo` is an error, because Hydra would otherwise
    generate a secret nobody knows. There is no `client_secret` attribute at all.
  * `grant_types` has no hard whitelist: unknown values only warn (Hydra does not validate them);
    `urn:ietf:params:oauth:grant-type:jwt-bearer` and `...:device_code` are known.
  * `metadata` / `jwks` are JSON strings compared semantically; lifespans are durations compared
    by value (`10m` == `10m0s`), also right after `import`.
  * Server defaults (`scope`, `token_endpoint_auth_method`, `subject_type`, ...) are
    Optional+Computed with `UseStateForUnknown`.
  * Update is a full `PUT` (Hydra replaces the whole client); lifespans are re-applied with
    `PUT /admin/clients/{id}/lifespans` if Hydra reports different values.
  * A client deleted outside OpenTofu (404, or 401 from older Hydra) is removed from state and
    re-created on the next apply.
* **New `hydra_trusted_jwt_grant_issuer`** (create/get/delete only, so changes replace): validates
  that `jwk` is a single public JWK with `kid`, `expires_at` is RFC 3339 in the future (compared
  as an instant, rounded to seconds). Hydra does not return the JWK, so after `import` it is taken
  from configuration; replacement happens only when the `kid` or the key material changes.

Known trade-off: removing an Optional+Computed server-default attribute (e.g. `scope`) from the
configuration keeps the last value instead of resetting it to Hydra's default - set it explicitly.

## Hydra v26.2.0 behaviour (verified locally)

`internal/empirical` contains executable checks against a real `oryd/hydra:v26.2.0`:

1. A trust's `expires_at` is **not enforced** when the assertion carries a `kid` header (only
   without `kid`). Hydra also accepts an `expires_at` in the past.
2. Deleting a trust deletes its JWK `(issuer, kid)`; another trust using the same key is
   **cascade-deleted** (FK `ON DELETE CASCADE`). Duplicate `(issuer, subject, kid)` -> 409.
3. `PUT /admin/clients/{id}` without `client_secret` keeps the secret; with one it rotates it.
4. Lifespans in the create body are applied.
5. A public client (`token_endpoint_auth_method = "none"`) can use the jwt-bearer grant
   (`client_id` in the form body); `max_ttl`, subject and scope restrictions are enforced.

Hence: no `create_before_destroy` on trusts, a fixed far-future `expires_at`, and one subject per key.

## Development

Requirements: Go (see `go.mod`), OpenTofu >= 1.11, Podman (or Docker) with compose.

```sh
make test          # unit tests
make hydra-up      # podman compose up -d --wait  (local oryd/hydra:v26.2.0, in-memory)
make testacc       # TF_ACC=1: acceptance tests + empirical checks (uses tofu if installed)
make empirical     # only the Hydra behaviour checks
make hydra-down    # podman compose down -v
make docs          # regenerate docs/ with tfplugindocs
make lint          # gofmt + go vet
```

With Docker: `make hydra-up COMPOSE="docker compose"` (and the same for `hydra-down`).
On macOS Podman needs a running machine (`podman machine start`).
CI (`.github/workflows/ci.yml`) uses Docker, which is preinstalled on `ubuntu-latest`.

## Releasing (owner checklist)

`origin` is the fork `nitra/terraform-provider-hydra`; `upstream` is `svrakitin/terraform-provider-hydra`.
Upstream tags `v0.1.0`…`v0.5.4` are inherited from the fork history, so this provider's versions
start at `v1.0.0` (breaking rewrite on terraform-plugin-framework).

1. Signing: organization secrets `GPG_PRIVATE_KEY` and `PASSPHRASE` (org `nitra`, selected repos
   `terraform-provider-dremio` and `terraform-provider-hydra`) hold the "nitra" provider signing key
   (fingerprint `45C2 CCEF 6BFD 58A1 74CF 493F 6F2A 3A28 C09B 5302`, already registered at
   registry.opentofu.org for the `nitra` namespace). Source of truth: Infisical, path `/terraform-providers`.
2. Make sure CI is green, then tag: `git tag -a v1.0.0 -m v1.0.0 && git push origin v1.0.0`. The `release`
   workflow (goreleaser) publishes zips, `SHA256SUMS`, its signature and the
   `_manifest.json` (protocol 6.0).
3. First release only: open a "Submit new provider" issue in
   [opentofu/registry](https://github.com/opentofu/registry/issues/new/choose) for `nitra/terraform-provider-hydra`.
